# 두 검증 환경과 KODA 대시보드 적용안

## 사용자의 판단

제3자가 KODA 대시보드에 접근하는 방식이 실제 업무에서 받아들여질지는 아직 확인되지 않았다. 따라서 한 경로를 확정하지 않고, 대시보드 이용과 별도 환경 실행을 모두 준비해 KODA의 피드백을 받는다. 현재 좋았던 검증 버튼·Ethereum 조회·응답·PDF 대조 흐름은 유지한다. 디자인은 내용을 표현하기 위한 수단이며, 기술 자체와 주체·처리 위치가 사라져서는 안 된다.

## 02 대시보드

제공된 `현재화면.png`의 조직 표시, 왼쪽 업무 메뉴, 감사/메시지 서명 검증 문맥, 흰 메뉴와 회색 본문을 참고했다. 실제 고객 잔고·결재 권한이 외부 수신자에게 부여됐다고 가정하지 않고, 외부 수신자의 증빙 검증 화면으로 한정했다. 새 기능임을 제품 창 바깥의 ‘KODA 대시보드 적용안 · 서비스 화면 제안’으로 구분했다.

파일 선택, 실제 검증 버튼, 관측된 Ethereum 응답 이동, 해시 대조와 세 질문의 결과는 그대로 연결했다. 작은 전체 구조도에는 ‘제3자’를 유지하고, 은행·거래상대방·외부 감사인을 아래 한 줄에 표시했다.

## 03 외부 검증 초안

독립 실행 번들, 검증 규격, 읽을 수 있는 소스, 고정 신뢰 기준, 의존성 라이선스를 담은 ZIP을 제공한다. Node.js 환경에서 대시보드와 같은 검증 함수를 실행하며 지갑 승인이나 새 거래를 만들지 않는다. 실제 원본·변경본 실행 결과를 manifest와 보고서로 보존했다.

03의 화면은 보존된 외부 실행 결과를 보여준다. 버튼을 누르면 외부 컴퓨터에서 새 검증이 실행된 것처럼 표현하지 않는다. 사용자가 내려받은 코드에 실제 PDF와 JSON을 넣으면 본인의 환경에서 새 조회를 수행할 수 있다. 이것은 실행 환경의 분리이며, 별도 기관의 코드 감사나 RPC 의존 제거를 의미하지 않는다.

## 기술과 기획서

SHA-256, EIP-712/ECDSA secp256k1, Solidity/OpenZeppelin DocumentRegistry와 기존 판정 로직을 바꾸지 않았다. 기획서 8.7에 최신 범위를 추가하고 1~2의 내용을 보존했다. 공식 발급자 인증·계정 권한·키 교체·폐기·RPC 운영은 미확정이다. 서명된 다른 원본이 등록 기준과 충돌하는 보조 사례도 이번 변경에 포함하지 않는다.

기술 어펜딕스는 14장 초안으로 만들었다. 기술 정의, 입력·처리·결과, 현재 사용 위치, 증명 범위와 한계를 나눴다. 구조도의 회색·진한 글자·초록/민트와 편집 가능한 도식을 사용했다. 본문의 두 검증 경로는 순차 단계가 아니라 같은 입력에서 갈라지는 두 선택지로 표시했다.

## 검증

- live 단위·컨트랙트 회귀 **47/47**, TypeScript 및 공유 경로 빌드 통과. 기존 번들 크기 경고는 남는다.
- 기존 파일 전달과 실제 원본 일치·변경본 불일치, 느린 응답·오류·재생·입력 교체·reduced motion 회귀 통과.
- 03 실제 실행 보고서 전환과 ZIP 다운로드 확인. 기록 보기는 새로운 RPC 실행을 발생시키지 않음.
- 1440/1280/390px 세 장면 가로 넘침·브라우저 예외 없음. 지갑 승인·서명·거래 요청 없음.
- 외부 ZIP을 별도 폴더에 풀어 원본 `match`, 변경본 `file-mismatch` 확인. 입력 거절 6건 자동 검사, 잘못된 입력의 체인 trace 없음.
- 부록 14장 모두 렌더링해 글자 배치와 도식을 확인함. 슬라이드 편집 대상은 저장된 Spaces 프레젠테이션이며 로컬 PPTX를 별도로 제작했다고 주장하지 않음.

## 포트폴리오 기여

신기호는 외부 수신자의 대시보드 이용을 당연한 전제로 두지 않고, 서비스 접근 경로를 두 안으로 준비해 현업 피드백을 받도록 제안했다. 동시에 실제 KODA 제품과의 시각적 연결, 기술 흐름의 가시성, 기술을 이해하고 구체적으로 피드백할 수 있는 부록을 요구했다. 이번 작업은 그 요구를 기존 검증 로직의 재사용, 별도 실행 패키지, 실제 판정 결과와 기술 설명 자료로 연결했다.

## 실제 거래를 발표에서 보여주는 방식 — 제안만 기록

이미 남긴 배포·등록 거래와 컨트랙트 주소를 짧게 확인한 뒤, 핵심 장면에서 현재 체인 기록을 새로 조회하는 방식이 적합하다. 새 발급의 지갑 연결·서명·등록·최종 확정 대기는 사전 녹화 또는 질의응답용으로 두는 편이 발표 흐름을 지키기 쉽다. 보존 기록과 현재 조회를 구분해야 한다. 이번에는 이 연출을 추가 구현하거나 새 거래를 제출하지 않았다.
