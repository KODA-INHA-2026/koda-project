# 검증 과정의 속도와 자산·기록 체인의 구분

2026-11-06. 사용자가 실제 데모를 보고 제시한 피드백을 반영한 후속 설계 기록이다. 피그마 자료 확인은 사용자의 요청에 따라 중단한 상태로 유지했다. 이번 변경에서 추가 외부 리서치는 하지 않았다.

## 사용자 문제의식

- ‘제출받은 PDF를 발급 기록과 대조합니다’ 장면에서 기술 처리가 너무 빨리 지나가 발표자가 설명하기 어렵다.
- Ethereum은 고객 BTC가 올라가는 곳이 아니라, 발급 문서의 검증정보를 남기는 곳이다. 작은 보조 설명으로도 이 구분이 드러나야 한다.
- ‘체인 밖 · BTC 수량’은 PDF에 적힌 잔고와 실제 자산을 혼동하게 할 수 있다.
- 구조도 화살표의 굽음이 기술적인 의미인지, 배치를 위한 표현인지 불명확하다.

사용자는 동작 속도를 지적하면서도 기술을 숨기거나 새 업무 흐름을 만들 것을 요구하지 않았다. 핵심은 **실제로 일어난 일을 청중이 따라갈 수 있는 속도로 설명하고, 업무 주체·처리 위치·기록 대상을 정확히 구분하는 것**이다.

## 구현 결정

### 실제 검증과 기록 설명의 시간 구분

실제 계산과 RPC 호출에 인위적인 대기를 넣지 않는다. 결과가 나오면 제3자 UI에 즉시 표시하고, 옆의 기술 과정과 구조도는 이번에 실행한 기록을 단계당 3.5초씩 다시 보여준다.

- ‘처리 기록 다시 보기’, ‘실행 종료’를 명시한다. 재생 중 추가 RPC는 없다.
- 실제 단계별 성공·불일치·확정 대기·실패 상태는 그대로 유지한다. 재생 위치가 성공 여부를 결정하지 않는다.
- 일시정지, 이전/다음, 단계 번호 직접 선택을 제공한다.
- 실행되지 않은 단계는 재생하지 않는다. 조기 실패에서는 시도한 구간만 남는다.
- 파일 선택·재검증·장면 이동 시 이전 재생을 정리한다.
- 동작 줄이기 설정에서는 자동재생을 끄고 수동 선택을 제공한다.
- 체인 조회가 실패한 경우에도 시도한 조회 위치는 표시하되, 응답 완료 경로와 완료 상태를 켜지 않는다. 재생 경로에는 흐르는 애니메이션을 쓰지 않는다.

### 자산과 증명서 데이터 구분

구조도 하단의 문구:

> 증명 대상: Bitcoin 네트워크의 BTC  
> Ethereum에는 문서 검증정보만 기록  
> PDF 원문·고객명·문서에 기재된 잔고는 미등록

‘잔고를 등록하지 않는다’는 것은 **증명서의 숫자 필드를 Ethereum 컨트랙트에 직접 저장하지 않는다**는 뜻이다. 실제 BTC가 블록체인 밖에 있다는 뜻이 아니다. 전체 PDF의 해시에는 그 숫자를 포함한 문서 전체 바이트가 반영된다. 숫자나 이름을 바꾸면 해시가 달라지는 기존 검증 방식은 유지한다.

### 화살표 구분

기존 곡선은 등록·조회·응답을 분리하기 위한 배치였으며 프로토콜상의 특별한 의미는 없다. 등록은 KODA→Ethereum, 조회는 제3자→Ethereum, 응답은 Ethereum→제3자로 직각 경로를 분리했다. 등록 라벨은 선을 가리지 않도록 옆에 배치한다.

## 기여와 범위

신기호는 실제 화면을 기준으로 설명 속도와 자산·기록 데이터의 혼동 가능성을 찾아 수정 방향을 제시했다. AI는 그 피드백을 상태·재생 동작·문구·경로 배치로 구체화하고 구현 및 회귀 검증을 수행했다. 컨트랙트, 서명, 등록 데이터, 원본 PDF, 판정 조건을 변경하는 작업이 아니다. 새로운 거래나 지갑 승인을 요청하지 않는다.

재생 속도가 실제 발표에 적절한지에 대한 청중 평가는 아직 없다. 3.5초는 조절 가능한 첫 구현값이며 수동 정지로 설명 시간을 확보한다.
