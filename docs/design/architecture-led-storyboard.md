# 전체 구조와 현재 동작을 함께 보여주는 연출

2026-11-06 첫 공유본 피드백: 기술값이 많아 피로하고 데모의 주장이 읽히지 않는다. 이전의 직관성과 현재의 기술 정확성 사이로 조정한다.

## 변경 범위

- 왼쪽 고정 구조: KODA → 고객사 → 제3자, 아래 공통 Ethereum. 현재 위치·방향을 강조한다.
- 오른쪽 현재 동작: PDF, 해시 계산, 발급서명, 컨트랙트 검사, 블록 포함·확정, 원본 전달, 실제 검증 UI.
- 긴 해시·서명·RPC 로그는 해당 장면의 기술값 펼치기로 이동한다. 기술 이름과 입출력, 발생 위치, 현재 상태는 기본 화면에 남긴다.
- 검증기·지갑·PDF 생성·컨트랙트·등록한 문서와 신뢰 기준은 그대로 사용한다. 연출 시간을 실제 네트워크 처리 시간으로 표시하지 않는다.

## 장면별 전달할 한 가지

| 장면 | 현재 위치 | 보여줄 동작 | 의미 |
| --- | --- | --- | --- |
| 전체 | 전체 구조 | 발급 문서와 제출 문서를 공통 기록으로 연결 | 발급 이후 제3자가 직접 대조하는 서비스 |
| PDF | KODA | 기준시점이 적힌 최종 PDF | 기존 증빙 발급이 출발점 |
| 해시 | KODA 측 브라우저 | 전체 파일 → SHA-256 | 대조할 원본 기준을 계산 |
| 서명 | 시험 발급자 MetaMask | ID·해시·시각 + domain → EIP-712 서명 | 어느 발급키가 어떤 정보에 서명했는가 |
| 등록 | KODA → Ethereum | register → 권한·서명·중복 검사 → 기록 | 같은 ID를 덮어쓸 수 없는 공개 기준 |
| 블록 | Ethereum | 등록 거래의 포함과 finalized를 구분 | 포함만으로 최종 확정이라고 하지 않음 |
| 전달 | KODA → 고객사 → 제3자 | PDF 보관·제출 | 원본은 고객사, 검증 기준은 체인 |
| 검증 | 제3자 ↔ Ethereum | 실제 로컬 연산·RPC 조회·대조 | 발급기관의 현재 응답에만 의존하지 않는 공개 기록 조회 |

## 가치 설명의 경계

디지털서명만으로도, 신뢰할 발급자 공개키와 서명 패키지가 있다면 출처·원본 대조가 가능하다. 블록체인만이 이 기능을 처음 가능하게 했다고 주장하지 않는다. 이번 컨트랙트가 더하는 것은 공개된 확정 등록 기준과 동일 ID 덮어쓰기 제한, 제3자의 재조회 경로다. 단일 공개 RPC를 사용하는 데모의 조회 신뢰 가정은 남아 있다.

BTC 잔고의 사실성, 공식 KODA 키 신원, 모든 중간 변경 이력, 철회·정정은 이 구현이 증명하지 않는다. 블록 연결 그림은 구조 설명이고 실제 추가 블록·검증자 응답을 만들어 보여주지 않는다.

## 검증 기준

기존 live 테스트, TypeScript와 빌드, 8개 장면의 현재 위치·표현, 데스크톱·좁은 화면, 실제 원본/변경본 조회, 키보드 조작과 모션 축소 처리를 확인한다. 실제 새 지갑 승인은 필요하지 않다.

## 구현·검증 결과

- `Presentation.tsx`와 `presentation.css`를 전체 구조 + 현재 장면 구성으로 변경했다. 제3자 화면에서만 제품 UI를 사용한다.
- `ArchitectureMap.tsx`와 `architecture-state.ts`가 실제 trace ID와 결과에 맞춰 위치·조회 방향·완료 여부를 표시한다. RPC 장애, 입력 오류, 미확정은 완료 경로로 표시하지 않는다.
- 원래 검증기·컨트랙트·PDF·기존 등록 증거는 변경하지 않았다.
- live 테스트 26/26, 최종 지도 상태 테스트 5/5, TypeScript와 프로덕션 빌드 통과. 번들 크기 500 kB 경고는 남아 있다.
- Chrome 1440×900 및 390×844에서 8개 장면을 확인했다. 수평 넘침 없음, Ethereum 지도 유지, 기술값 펼치기, 기록 재생·일시정지, Enter 키로 다음 장면 이동을 확인했다.
- 실제 공개 RPC에서 원본 일치·변경본 불일치를 확인했다. 검증 시작 시 지도에 `제3자 → Ethereum / 컨트랙트 코드·발급자 확인`이 나타나고, 종료 시 실제 결과를 표시했다.
- 모션 축소 CSS와 설정 변경 감지 코드는 반영했다. OS 설정 전환과 스크린리더 검수는 이번 세션에서 실행하지 않았다.

이 구성의 제안과 내용 우선·전체 위치 우선 판단은 사용자의 피드백에서 나왔다. AI 도구는 구현·기술 정합성 검토·테스트·화면 검수를 보조했다. 사용자는 이전 공개본을 팀에 공유하지 않았으며, 이번 구조도 중심 버전을 같은 공유 주소에 게시하도록 요청했다. 이전 버전은 Git 이력에 보존한다.

## 팀 공유와 외부 검증 확장

발표에서는 KODA 대시보드를 가정한 제3자 검증 화면을 중심으로 설명한다. 실제 KODA 운영 대시보드와 연동한 것은 아니다. 검증정보·규격·코드를 묶어 다른 환경에서 재현하는 외부 검증 패키지는 확장 방향으로만 언급하며, 이번 데모에 구현·배포한 기능으로 표현하지 않는다.

현재 데모의 독립적 검증은 제출 파일의 로컬 해시 계산·서명자 복구와 공개 체인 기록의 직접 조회·대조에서 설명한다. 화면의 제공 주체와 검증 근거의 출처를 구분하고, 발급자·컨트랙트 신뢰 기준 및 공개 RPC 의존성은 남는 전제로 명시한다.
