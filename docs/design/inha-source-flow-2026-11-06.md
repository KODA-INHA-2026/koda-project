# 인하테크홀딩스 기본 자료와 수탁정보→PDF 연결

사용자는 점검 결과 중 1번 기본 자료 교체와 2번 원천정보 연결만 진행하도록 지정했다. 재서명 비교 사례와 검증 규칙·컨트랙트는 이번 변경에 포함하지 않는다.

## 변경

- 기본 자료를 실제 확정된 인하테크홀딩스㈜ 100 BTC PDF·검증 JSON·등록 블록 `12076051`로 교체했다. 새 서명이나 거래를 요청하지 않았다.
- 03 외부 검증 ZIP의 예시 JSON과 실제 실행 보고서를 같은 인하 자료로 다시 만들었다. 원본 `match`, 120 BTC 변경본 `file-mismatch`를 실제 공개 RPC에서 확인했다.
- 01의 기존 흐름 위에 KODA의 가상 수탁정보를 놓고 법인명·수탁 BTC 전체 잔고·잔고 기준시점이 같은 정보로 PDF에 들어가는 연결을 표시했다. 별도 장면이나 KODA·고객사 제품 UI를 추가하지 않았다.
- `DEMO_CUSTODY_SNAPSHOT`을 PDF 생성기와 화면이 공유한다. 기존 PDF 바이트가 변하지 않음을 등록 해시 및 보존 원본과 비교했다. 실제 KODA 원장 연동이나 잔고의 사실성 검증으로 표현하지 않는다.
- 과거 한울 PDF와 증거는 그대로 보존한다. 과거 PDF 재생성 도구도 최신 등록 포인터 대신 과거의 고정 증거를 읽도록 바로잡았다.

## 검증

- live 회귀 47/47, TypeScript 및 공유 빌드 통과. 최초 제한된 실행에서는 로컬 시험 체인이 시작되지 않아 4개 검사가 실행 환경 오류로 실패했고, 로컬 체인을 실행할 수 있는 환경에서 재실행해 전체 통과했다.
- 웹에서 실제 인하 PDF·JSON을 내려받은 뒤 별도 수신자 환경에 입력해 실제 RPC 원본 일치·변경본 불일치를 확인했다.
- RPC 실패·미확인 상태, 일시정지·재생·다시보기·동작 줄이기, 지갑 연결 대기와 검증 진행의 분리를 재확인했다.
- 외부 실행 입력 거절 6건과 지갑·쓰기 호출 부재를 확인했다.
- 1440/1280/390px에서 수탁정보·PDF 순서와 화면을 확인했다. 작은 화면의 과도한 여백과 좁은 데스크톱의 검증정보/체인 영역 겹침도 조정했다.
- 기존 Vite 500 kB 이상 번들 경고는 남는다. 이번 변경에서 검증 보안 규칙이나 패키지를 추가하지 않았다.

## 기여 기록

대표님이 강조한 내부 정보와 외부 증빙의 연결을, 새 기능을 임의로 확대하지 않고 가상 원천정보와 실제 PDF 생성의 동일 데이터 사용으로 구체화했다. 실제 등록 원본을 바꾸어 이름만 교체하는 오류를 피하고, 신규 발급본의 바이트·서명·거래를 웹과 외부 실행 자료에 일관되게 반영했다.
