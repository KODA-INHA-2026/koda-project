# 대표님 네 단계와 외부 검증 초안 — 재구성

사용자 승인 범위: 01 원본 발급 → 02 전자서명·해시 생성 → 03 블록체인 기록 → 04 제3자의 대조·검증. 05는 같은 검증을 외부 환경에서 수행하는 초안이다. 대표님 원문의 단계와 발표 장면을 직접 대응시키되, 앞 세 장면을 짧게 넘기고 검증에 충분한 비중을 둔다.

## 변경 계획

- 01–03은 하나의 가상 인하테크홀딩스 PDF를 이어서 다룬다. 서비스 대시보드를 새로 만들지 않고 원천정보·문서·해시·서명·등록 기록의 관계를 보여준다.
- 01은 원천정보와 PDF, 02는 같은 PDF에서 SHA-256 후 EIP-712 서명, 03은 DocumentRegistry 등록과 KODA→고객사→제3자의 파일 전달을 보여준다.
- 강제 자동 진행·새 지갑 승인·장면 진입에 따른 체인 쓰기 작업은 없다. 발표자는 앞 세 장면을 바로 넘길 수 있다. 기록은 실제 보존된 거래에 근거하고, live 준비 모드의 미완료 상태를 성공처럼 표시하지 않는다.
- 04의 대시보드, 원본/변경본/재서명 비교, 실제 RPC 조회와 요청·응답 연출, 세 질문 결과를 유지한다. 파일 입력은 선호한 세로 배치를 유지한다.
- 기존 `?view=verify`와 `?view=external` 링크를 유지하며 각각 04·05로 연결한다. live 처리 단계와 발표 장면 매핑을 갱신하고 장면 이동으로 선택 파일·결과가 소실되지 않게 한다.
- 05는 외부 환경의 보존 실행 기록과 실행 패키지라는 현재 구현 범위를 유지한다. 검증 뒤에 반드시 거치는 다음 처리 단계로 표현하지 않는다.

## 영향 범위와 검수

Presentation, IssuerScenes, 발표 순서/URL 매핑, 관련 CSS, 04·05 번호·연결 문구와 테스트를 수정한다. 검증 함수·컨트랙트·서명·PDF 생성 규격과 실제 fixture는 수정하지 않는다. 기술 부록의 과거 02·03 번호는 현재 장면 번호와 대응 안내를 추가한다. 사용자 직접 작성 메모는 수정하지 않는다.

기존 live 회귀 → 장면/URL/live stage 매핑 테스트 → 타입검사·빌드 → 브라우저 5장면 이동·입력/결과 보존·실제 원본/변경본/재서명 RPC 검증·RPC 실패·reduced motion·1280/1536/390 화면 확인 순서로 검수한다. 문서·이미지의 구현 증거는 같은 날짜 폴더에 보존한다.

## 설계 판단과 기여 기록

사용자가 제기한 문제는 대표님이 나눈 업무·기술 단계가 데모의 두 장면 안에 묶이면서 각 단계의 역할이 흐려질 수 있다는 점이었다. 동시에, 앞 과정을 길게 설명하다 핵심인 제3자 검증이 짧게 지나갔던 이전 문제를 반복하지 않도록 요구했다.

이에 01–04의 단계는 분리하되 01–03에서 같은 문서 ID와 PDF를 이어서 보여준다. 발표자는 자동 재생을 기다리지 않고 바로 다음 단계로 이동한다. 03에서는 등록 기록 아래에 KODA→고객사→제3자 전달 관계와 실제 자료 다운로드를 배치하고, 04의 검증 화면으로 연결한다. 05는 04와 다른 검증 환경을 논의하기 위한 초안이다.

문제의식·재구성 방향·보존할 표현과 기능의 기준은 사용자가 제시했다. AI는 그 기준에 맞춰 화면, 장면 매핑, 문구, 검수 코드를 구현했다. 대표님 답변이나 팀장 의견에서 확인되지 않은 운영 정책·제품 기능을 새로 확정하지 않았다. 기술·계약을 새로 설계하거나 새 등록 거래를 발생시킨 작업도 아니다.

사용자가 직접 쓰는 `기여와 쉬운 언어로 설명.md`는 이 기록과 별개로 유지하며 수정하지 않는다. 실제 발표자의 피드백과 청중 이해도 평가는 이후 확인할 사항이다.

## 구현 검수

- [최종 검수 요약](five-stage-2026-11-07/verification-summary.md): 전체 live 테스트 56/56 통과. 다섯 장면을 이동한 뒤에도 선택 파일과 검증 결과가 유지된다.
- TypeScript 검사와 공유 경로용 빌드 통과. 기존 500 kB 초과 번들 경고는 남아 있으며 이번 변경에서 의존성을 추가하지 않았다.
- [브라우저 회귀 기록](five-stage-2026-11-07/browser-check.json): 실제 PDF·JSON 다운로드와 별도 수신 환경의 업로드, 원본 일치·변경본 불일치, RPC 오류, 일시정지·다시 보기·reduced motion, 05 보존 실행 결과를 확인했다.
- [레이아웃 확인](five-stage-2026-11-07/visual/layout-check.json): 1536·1280·390px에서 다섯 장면 모두 가로 넘침과 브라우저 예외가 없었다. 파일 선택 영역은 세로 배치를 유지했다.
- [재서명 비교 검수](five-stage-2026-11-07/signed-comparison/browser-check.json): 사용자 승인 서명의 120 BTC 문서는 로컬 서명·파일 검사를 통과하지만 실제 확정 등록 원본과 달라 실패한다. RPC 실패 시 이전 대조 결과나 반환 해시를 성공처럼 남기지 않는다.
- 검증 함수·계약·PDF 생성·서명 규격·기존 거래 및 fixture는 변경하지 않았다. 기존 `view=verify`·`view=external` 주소는 각각 04·05로 연결한다.
