# 제안의 중심을 되찾는 두 장면

사용자 지적: 피드백을 순차적으로 더하면서 앞서 잘 읽히던 흐름이 사라졌다. 기술을 드러내라는 요청을 기술 정보의 양으로 해석했고, 제3자 검증이라는 제안의 중심보다 장면·설명 도구가 커졌다. 이번 작업은 표현을 더 얹는 것이 아니라 두 가지 핵심 사건으로 다시 구성한다.

## 유지할 두 문장

1. KODA가 증명서를 고객사에 전달하면서, 그 원본을 대조할 검증정보를 Ethereum에 등록한다.
2. 제3자가 고객사로부터 받은 PDF를 KODA 대시보드에서 Ethereum 기록과 대조한다.

대표님 세 질문, 실제 발급서명·등록·조회 검증, 고객사의 원본 보관, Bitcoin의 네이티브 BTC와 Ethereum 문서 기록의 구분은 유지한다. 같은 업무 주체를 배경 박스에 중복해서 그리지 않는다. 제3자의 조회는 Ethereum에만 향한다.

## 수정 계획과 경계

- 일곱 장면과 여러 단계 탐색 UI를 두 발표 장면으로 줄인다. 첫 장면은 발급 PDF에서 고객사와 Ethereum으로 갈라지는 두 경로, 두 번째는 한 대시보드에서 조회·응답·대조·결과가 이어지는 사건이다.
- 제품 UI는 제3자에게만 제공한다. 발급·등록은 문서와 기록이 이동하는 열린 캔버스로 보인다.
- 문구·상자·반복 설명을 줄이고 여백과 크기로 중요도를 정한다. 긴 해시·서명 필드·finality·RPC 설명은 부록과 닫힌 상세에 둔다.
- 재생은 실제 결과와 분리한다. 실제 판정은 즉시 표시하고, 관측한 처리의 설명만 천천히 재생한다. 재생으로 새 호출이나 성공을 만들어내지 않는다.
- 컨트랙트, 서명, PDF 바이트, 실제 검증 함수와 지갑 로직은 수정하지 않는다. 새 의존성·배포·서명 승인 요청을 추가하지 않는다.

## 검증 기준

기존 검증·컨트랙트 회귀 테스트를 먼저 실행한다. 변경 후 두 장면 이동, 실제 원본/변경본, 오류와 대기, 재생 중 추가 RPC 없음, 파일 교체 시 이전 결과·재생 초기화, 입력 유지, reduced motion·키보드·모바일을 확인한다. 두 장면을 각각 한 문장으로 설명할 수 있는지 화면을 직접 보고 검토한다. 기능 검사 통과를 청중 이해도 개선의 증거로 주장하지 않는다.

세부 기술의 기준 문서는 [기술 부록](../presentation/blockchain-technology-appendix-draft.md)이다. 기존 [토스 자료 적용 기록](toss-research-application-2026-11-06.md)을 재검토했으며 이번에는 추가 리서치를 했다고 주장하지 않는다. 문제는 자료 부족보다 내용의 우선순위를 화면에 반영하지 못한 데 있다고 판단했다. Figma 작업은 계속 중단한다.

## 구현과 확인 결과

- 발표 이동은 두 장면이다. 발급 내부 설명은 한 캔버스에서 강조만 바뀌며, 제3자는 하나의 대시보드에서 파일을 바꾸고 재검증한다.
- 별도 수탁 배경 박스를 제거하고 같은 KODA·고객사에 Bitcoin 관계를 직접 연결했다. 제3자 조회·응답은 Ethereum에만 연결되고 현재 경로를 강조한다.
- 대시보드에서 선택한 PDF가 오른쪽 처리로 이어지고, 대조 결과가 대시보드로 돌아오는 연결을 추가했다. 기록을 읽을 때는 기존 블록을 강조하며 새 블록이 생기는 연출은 없다.
- 실제 결과는 즉시 표시한다. 방금 관측한 주요 처리는 5초씩 설명 재생하며 일시정지·수동 이동을 지원한다. 재생 중 추가 RPC는 없고 실패한 검증에서 수행하지 않은 단계를 표시하지 않는다.
- 긴 해시, 서명 필드, 호출 순서, finality는 닫힌 기술 상세와 부록으로 옮겼다. 부록에는 두 장면에서 보인 동작과 각 기술 설명의 대응표를 추가했다.
- 기존/변경 회귀 테스트 39개 통과. 마지막 결과 문구 수정 후 관련 상태 테스트 3개를 재실행해 통과했다. 최종 TypeScript·프로덕션 빌드 통과. 기존 단일 JS 번들 500 kB 경고는 남는다.
- 실제 Sepolia 조회에서 원본 일치·120 BTC 변경본 불일치 확인. 오류 응답을 주입해 검증 미완료, 확인하지 못한 해시·결과를 성공처럼 표시하지 않음을 확인했다.
- 두 장면과 발급 내부 강조를 1440/1280/390px에서 확인했다. 가로 넘침·브라우저 오류 없음. 키보드·reduced motion·입력 유지·재생 초기화도 확인했다. 새 지갑 서명·등록 거래·게시 작업은 수행하지 않았다.

사용자의 기여는 반복 피드백의 중심을 다시 짚고, 발표를 두 사건으로 재구성하며, 기술 설명을 부록으로 분리하고 구조도에 업무 주체를 한 번만 표시하도록 방향을 바로잡은 데 있다. AI는 이 기준에 따라 화면·상태·검증 코드를 수정했다. 이 기록은 구현 결과이지 디자인이 사용자의 기대를 충족했다는 판정은 아니다. 최종 연출에 대한 사용자 피드백은 아직 받지 않았다.
