# 구조도 중심 데모 고도화 검토 — 2026-11-06

## 현재 기준과 이번 반영

사용자가 처음 두 버전보다 나아졌다고 판단한 구조도 중심 버전을 후속 작업의 초안으로 삼는다. 전체 구조와 현재 장면을 함께 보여주는 구성, KODA·고객사·제3자의 역할, 등록과 조회 양쪽의 Ethereum 연결, 제3자에게만 제품 UI를 보여주는 원칙을 유지한다. 색상은 KODA의 초록·민트 계열을 유지한다.

이번에는 기획 체인과 테스트 환경의 표현을 정리했다. 구조도·블록 그림·발표 안내의 중심은 **Ethereum**이다. 별도 실행 정보에는 **Sepolia 테스트넷**을 명시한다. 실제 서명 domain의 chainId 11155111, RPC, 거래·컨트랙트 주소, 검증 조건은 변경하지 않았다. 실제 테스트 기록을 메인넷 기록으로 표현하지 않는다.

## 개선 우선순위

아래는 코드·보존 화면·현재 브라우저 화면을 검토한 제안이다. 새로운 업무 기능을 확정한 목록이 아니다.

| 우선순위 | 현재 부족한 점 | 다음 수정 방향 |
| --- | --- | --- |
| 1 | 기본 검증 화면의 처리 순서는 해시 계산→조회→대조만 강조한다. 발급서명 복구와 허용 발급자 확인이 작게 처리되어 ‘발급 출처’ 판정의 근거가 잘 보이지 않는다. | PDF 해시 계산→발급서명·발급자 확인→확정된 등록 기록 조회→세 해시 대조를 연결한다. 실제 구현의 세부 순서와 병렬·선행 검사를 먼저 대조해 연출을 맞춘다. |
| 2 | PDF 선택만으로 어느 문서의 기록을 찾는지 알기 어렵다. 현재 데모는 문서 ID·서명·등록 거래·신뢰할 계약과 발급자를 사전 로드한다. | 제3자가 제출받은 PDF와 사전 제공된 검증정보를 함께 사용함을 표시한다. 임의의 PDF에서 자동으로 문서 ID를 찾는 기능처럼 보이지 않게 한다. 외부 패키지는 미구현 확장 방향으로 유지한다. |
| 3 | 원본→해시→서명→등록값→조회값이 장면마다 따로 나타나, 같은 문서의 값이 계속 이어진다는 느낌이 약하다. | 같은 문서와 해시에 일관된 표식을 사용하고 현재 활성 경로를 따라 전달되는 것을 보여준다. 실제 처리 완료와 발표용 재생을 구분하며 가짜 네트워크 이벤트를 만들지 않는다. |
| 4 | ‘원본 일치’와 ‘변경 여부’는 같은 `fileMatch` 결과를 두 관점으로 보여준다. 세 항목이 각각 별도의 기술적 증명처럼 읽힐 수 있다. | 사용자가 유지한 세 질문은 보존한다. 발급 출처는 서명·허용 발급자, 원본 일치는 세 해시 대조, 변경 여부는 **현재 제출본과 등록 원본의 차이**라고 설명한다. 중간 변경·복원 이력 전체를 보장하지 않는다. |
| 5 | 같은 ID 덮어쓰기 금지와 Ethereum 자체의 가치가 한 문단에 섞여 있다. | ‘이 컨트랙트가 강제하는 규칙’과 ‘공개 체인이 제공하는 확정 상태·공통 조회 기준’을 구분한다. 디지털서명만으로도 가능한 원본 검증을 블록체인만의 기능이라고 주장하지 않는다. |
| 6 | 전체 구조 위치 설명, 오른쪽 장면 번호, 하단 발표 번호가 반복된다. 장면 제목의 01~07과 하단 01~08이 어긋난다. 지도 안의 작은 글씨도 발표 거리에서 읽기 어렵다. | 번호 체계를 하나로 통일한다. 지도는 주체·체인·활성 경로에 집중하고, 기술 입력·처리·출력은 현재 장면에서 읽히게 한다. 기술을 삭제하는 대신 역할에 맞춰 배치한다. |
| 7 | 과거 실제 등록 증명서는 한울테크홀딩스㈜, 다음 신규 발급 설정은 인하테크홀딩스㈜다. 초기 복원 전후에 이름이 달라질 수 있다. | 기존 증거는 그대로 유지하고 사례를 명확히 표시한다. 인하테크홀딩스로 통일하는 신규 사례는 새 PDF 생성·서명·등록 승인을 받아야 한다. 기존 파일의 이름만 바꾸지 않는다. |

## 연출을 개선할 때의 기준

- 움직임은 무엇이 어느 주체·처리 위치에서 다른 곳으로 전달되는지 설명해야 한다. 단순히 반짝이거나 완료 표시가 순서대로 켜지는 것만으로 처리 과정을 대신하지 않는다.
- 실제 RPC는 빨리 끝날 수 있다. 설명을 위해 결과를 되짚는 재생은 별도 상태로 표시하고 실제 네트워크가 계속 처리 중인 것처럼 시간을 늘리지 않는다.
- 제3자 UI 옆에서도 로컬 계산과 공개 체인 읽기를 계속 구분한다. ‘앞부분 기술, 뒷부분 UI’로 분리하지 않는다.
- 발표에서는 KODA 대시보드를 가정한 1안에 집중한다. 외부 검증 패키지인 2안은 동일한 검증을 다른 환경에서 재현하도록 제공할 수 있다는 확장 방향이다.
