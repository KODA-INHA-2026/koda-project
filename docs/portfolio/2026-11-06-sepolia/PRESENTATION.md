# 실제 기술 실증을 발표용 경험으로 연결한 과정

> 초기 연출 개선 기록이다. 이후 사용자가 “디자인은 내용을 표현하는 방식이며, 제3자 UI에서도 기술 처리가 이어져야 한다”고 정정했다. 최신 장면 기준은 [전체 기술 시연 기준](../../design/technical-storyboard.md)을 따른다. 이 문서의 기존 화면 캡처와 최초 검수 한계는 당시 이력으로 보존한다.

## 사용자 결정과 적용

사용자는 기술 처리 과정이 시각적으로 드러나고, 제3자가 파일을 검증하는 장면만 서비스 UI처럼 보이도록 방향을 정했다. 기존 화면의 좌우 구성을 계승할 의무를 없애고, 원인과 결과를 보여주는 연출을 요청했다. 이후 Toss 공개 자료를 더 깊게 조사하되 **KODA의 초록·민트 컬러는 유지**하고, 첫 화면의 Bitcoin/Ethereum 병렬 비교는 혼동을 만들기 때문에 제거하도록 구체적으로 피드백했다.

이를 다음과 같이 반영했다.

- 첫 장면은 KODA가 발급한 문서를 제3자가 확인하는 문제로 시작한다.
- BTC는 PDF에 담긴 가상 고객 자산의 예시다. Ethereum은 문서 검증정보를 기록하는 단계에서 설명한다.
- 기술 장면은 원본 PDF, 실제 파일의 처음 24바이트와 전체 SHA-256, EIP-712 메시지·서명·domain, 컨트랙트 검사, 블록 포함·확정, 고객사 전달을 각각 보여준다.
- 제3자에게만 파일 선택·실제 RPC 조회·판정이라는 서비스 UI를 제공한다. 원본 지문·서명 지문·체인 지문 전문은 상세 정보로 둔다.
- 원본 재생은 명시적인 재생 버튼으로 시작하며, 일시정지·이전/다음·단계 이동·직접 검증 이동을 제공한다. 자동 재생 시간은 실제 체인 처리 시간이 아니다.
- 새 인하테크홀딩스㈜ 발급 시 화면에는 새 처리 중인 값만 표시한다. 기존 한울 기록의 서명·해시를 새 발급 결과처럼 보여주지 않는다.

## 조사 근거와 구현

[추가 공식 자료 8개와 기초 원칙](../../design/toss-research.md)을 문구·정보 위계·아이콘·상태 피드백에 적용했다. 색과 세부 수치·CSS는 KODA 데모의 자체 결정이다. 공개 Toss 원칙을 적용했다는 의미이며 실제 Toss 컴포넌트나 비공개 자산을 복제한 것이 아니다.

로컬 DFY Typography/Icon/Grid, PlusX Interaction `.fig` 파일은 썸네일 수준에서 확인했다. 이 확인을 전체 강의 학습이나 전체 Figma 프레임 분석으로 설명하지 않는다. 유료 강의 원본은 산출물에 포함하지 않았다.

핵심 파일은 `apps/web/src/live/Presentation.tsx`, `presentation.css`, `main.tsx`, `recorded-evidence.ts`이고, 지속할 디자인 기준은 루트 `DESIGN.md`다. 새 UI 의존성은 추가하지 않고 React·CSS·SVG로 구성했다.

## 검증 근거

- 실제 Chrome에서 공개 체인 조회 후 원본 `발급 원본과 일치해요`, 120 BTC 변경본 `제출한 파일이 발급 원본과 달라요`를 확인했다.
- 기록 재생의 단계 전환, 일시정지, 직접 장면 선택, PDF의 잔고 기준시점과 발급시각 분리, 실제 PDF 헤더 바이트와 SHA-256 표시를 확인했다.
- 컨트랙트·검증기·배포 상태·PDF 회귀 테스트 **20/20 통과**. 테스트는 로컬 EVM을 실제 실행하며 별도 Sepolia 거래를 보내지 않는다.
- 웹 TypeScript, 루트 TypeScript, Vite live 빌드와 diff 형식 검사를 통과했다. 번들 약 585KB 경고는 남아 있으며 발표 기능의 실패는 아니다.
- `screenshots/`에 데스크톱 화면을 보존했다. 일부 캡처 뒤 제목 줄바꿈·문구·PDF 그림자 등 작은 보정을 더 했으므로 소스가 최종 기준이다.

검증 한계: Chrome 원격 화면 크기 도구가 연결 오류를 반환해 **390px 모바일 실제 화면 검수는 완료하지 못했다**. 반응형 CSS와 reduced-motion 처리는 구현했고 코드로 확인했지만, 모바일·모션 축소의 실제 기기 검증이나 보조기술 접근성 인증을 마쳤다고 주장하지 않는다.

## 다음 사용자 행동

현재 공개 기록 재생과 제3자 대조는 추가 지갑 승인 없이 볼 수 있다. 다음 발급 사례를 인하테크홀딩스㈜로 바꾸어 체인에 새로 남길 때만 MetaMask에서 문서 서명과 등록 거래를 승인한다. 기존 계약 재배포는 필요 없다. 사용자가 쉬는 동안 새 지갑 요청은 띄우지 않았다.

사용자의 기여는 솔루션 범위·기술 적용 목적·아키텍처·시연의 관점과 시각적 기준을 결정하고, 혼동을 일으키는 표현을 바로잡은 데 있다. 구현·리서치·검증에는 AI 도구를 활용했다. 팀 전체 성과나 기업 자문을 개인 단독 성과로 바꾸지 않는다.
