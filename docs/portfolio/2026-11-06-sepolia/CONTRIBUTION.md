# 솔루션 설계부터 실제 Sepolia 실증까지

기록일: 2026-11-06 (KST). 개인 기여의 근거는 이 프로젝트 대화에서 확인한 담당 범위·제안·결정, 함께 정리한 기획서, 저장소 코드와 실행 증거다. 아래 내용은 포트폴리오 초안을 위한 사실 기록이며 팀 내부 역할의 최종 대외 표현은 팀과 조율할 수 있다.

## 역할과 출발점

팀원이 기획서 형식으로 정리한 초안에서 솔루션 3~8번의 기능 이해와 추가 설명이 필요한 상황이었다. 사용자는 **솔루션 파트**를 맡아, 대표님·COO의 자문을 중심에 두고 기능·기술·구조·시연 범위를 구체화했다.

팀이 맞춘 문제 흐름과 대표님이 제시한 방향에서 임의로 벗어나지 않는 것을 우선 기준으로 세웠다. 미확인된 실제 KODA 운영 방식은 사실로 채우지 않고, 제공자료에서 확인된 사실·팀의 설계안·가상 시연 설정을 구분하도록 요구했다. 이전 데모는 신규 구현의 기능 기준에서 제외했다.

## 팀·자문·도구와의 경계

- 문제정의와 사업 맥락, 대표님·COO가 제시한 방향은 공동의 출발점이다. 사용자의 독자 발명으로 표시하지 않는다.
- 사용자의 기여는 그 방향을 **검증 대상, 기능 범위, 자산·체인 역할, 데이터와 신뢰 구조, 데모 경험, 구현·실증 계획**으로 구체화하고 검토·수정한 과정이다.
- 세부 암호 방식·라이브러리·코드와 테스트 작성에는 AI 개발 도구의 조사·구현 보조를 활용했다. 사용자는 요구사항·범위·설명 기준·연출 방향을 제시하고 결과를 검토하며, 자신의 시험 지갑으로 배포·문서 서명·등록을 승인했다.
- 실제 KODA 운영키·운영망·고객 데이터·보관 자산을 사용한 작업은 아니다.

## 구현한 것과 증거

- `DocumentRegistry.sol`: 고정 시험 발급자, EIP-712 서명 복원, 최초 ID 등록, 변경·삭제·업그레이드 경로 없음.
- PDF·브라우저 처리: 최종 PDF 바이트의 SHA-256, 분리된 발급서명, 원본·수정본 생성과 비교.
- MetaMask 연동: 사용자 승인에 따른 배포·구조화 서명·등록 거래. 개인키를 코드로 가져오지 않음.
- 조회·검증: 거래 입력·영수증·등록 이벤트·정식 블록·finalized 계약 기록과 제출 파일을 연결.
- 예외 구분: 파일 불일치, 다른 서명자, 미등록, 확정 대기, 조회 실패를 다르게 처리.
- 검증: 실제 로컬 EVM 실행 테스트, 검증기·PDF·배포 진행 상태 테스트, 타입 검사, 브라우저 공개 RPC 조회. 실제 Sepolia 성과는 [배포 기록](DEPLOYMENT.md)과 그 시점의 JSON 증거를 따른다.

## 구현 완료와 후속 범위의 경계

- 실제 등록·원본 일치·변경본 불일치 결과는 [검증 기록](VERIFICATION.md)으로 확인했다.
- 기술 처리 장면과 제3자 UI를 구분한 기록 재생 연출을 구현했다. KODA 컬러 유지와 첫 화면 역할 혼동 제거를 포함한 사용자 피드백은 [연출 기록](PRESENTATION.md)에 남겼다. 모바일 실제 기기 검수와 새 회사명 등록은 남아 있다.
- 다른 사람에게 검증 패키지를 전달하는 연동, 외부 재현 키트, 운영 권한·키 교체·철회·정정 정책은 후속이다.
- 블록체인으로 PDF에 기재된 BTC 잔고의 사실성을 증명한 것이 아니다. 검증 범위는 발급 정보와 제출 파일의 연결 및 원본 동일성이다.

## 포트폴리오 서술용 초안

> KODA 산학협력 프로젝트에서 솔루션 설계 파트를 맡아, 대표·COO 자문과 팀의 문제정의를 제3자 문서 검증 시나리오로 구체화했다. 고객의 BTC 자산과 Ethereum의 문서 검증 기록을 구분하고, 원본 해시·발급서명·컨트랙트 등록·외부 조회를 연결하는 아키텍처와 시연 범위를 설계했다. AI 개발 도구의 보조를 활용해 구현·테스트를 진행하고, MetaMask로 Sepolia 컨트랙트를 실제 배포하고 가상 잔고 증명서의 서명·등록을 승인했다. 원본과 변경본을 공개 체인 기록에 대조해 각각 일치·불일치를 확인했다. 배포 포함과 최종 확정의 차이를 검증 기준에 반영하고, 기술 과정과 제3자 화면이 구분되는 시연을 구성했다.

이 문구는 현재 확보한 실제 거래·검증 결과와 연출 구현에 근거한 초안이다. 전체 팀의 기여나 기업 자문을 개인 단독 성과로 주장하지 않는다.
