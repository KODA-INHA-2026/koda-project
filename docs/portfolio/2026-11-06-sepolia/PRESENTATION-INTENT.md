# 발표 전달 설계 — 의도·문제의식·기여 기록

기록일: 2026-11-06. 작성 목적: 신기호가 솔루션 설계·기술 실증·발표 데모를 발전시키며 내린 판단과 그 근거를 포트폴리오에 남긴다. 현재 요청은 화면을 곧바로 고치는 것이 아니라 발표 내용·정보 배치·표현을 먼저 검토하는 것이다.

## 지금 해결하려는 문제

BTC 잔고 증명서의 검증정보를 실제 테스트넷에 등록하고 제3자가 조회·대조하는 기능은 동작한다. 전체 구조와 현재 장면을 함께 보여주는 버전도 이전 두 버전보다 낫다고 사용자가 판단했다. 그러나 구현한 내용을 청중에게 정확하고 자연스럽게 전달하는 완성도는 아직 충분하지 않다.

처음의 시각적 구성에서는 디자인이 전달할 내용을 앞서는 문제가 있었고, 이후 기술 정보를 늘린 구성에서는 정보가 과밀해 핵심을 파악하기 어려워졌다. 구조도 중심 버전으로 전체 맥락은 나아졌지만, 문구에 내부 설계 메모·추상적인 표현·번역투가 남아 있다. 사용자는 좋은 재료와 기능을 갖추는 것뿐 아니라 그것을 잘 보여주는 것 또한 자신의 역량이라고 보고, 이 단계에서 발표의 전달 방식을 다시 설계하려고 한다.

이는 사용자 피드백에 근거한 평가다. 팀원·심사위원 대상 사용성 조사나 이해도 측정으로 효과를 입증한 결과는 아직 없다.

## 사용자가 정한 중심과 우선순위

1. **대표님 답변이 과제의 중심이다.** KODA 증빙을 외부에 제출한 뒤 제3자가 출처·원본 일치·변경 여부를 확인하도록 한다. 팀과 대표님이 정한 범위를 임의로 확장하지 않는다.
2. **기술 구현은 그 방향을 구체화한 결과다.** 어떤 기술을 어디에, 왜 사용했으며 무엇을 확인할 수 있는지 실제 동작으로 보여준다. 기술 이름과 복잡한 해시값을 나열한 것만으로 설명을 마쳤다고 보지 않는다.
3. **디자인은 내용을 전달하는 방법이다.** 화면이 깔끔하다는 이유로 기술을 가리거나, 시각적으로 돋보인다는 이유로 다른 내용을 강조하지 않는다.
4. **토스 리서치는 전달 방법을 배우기 위한 근거다.** 문장·정보 위계·행동과 반응·상태 변화에서 인사이트를 얻는다. KODA의 색 정체성은 유지한다.
5. **보유한 피그마 강의자료도 설계 자산이다.** DFY·PlusX 자료를 타이포그래피·그리드·아이콘·인터랙션 검토에 활용하려는 의도가 있다. 자료가 있다는 사실과 실제 상세 프레임을 확인·적용한 범위는 구분한다.

사용자가 직접 표현한 기준:

> “디자인은 우리 내용을 표현하는 방식”
>
> “아무리 우리가 좋은 재료를 가지고 있어도 그걸 잘 보여내는것도 우리 실력이고 능력”

## 직접 발견한 문제의 사례

### 1. 역할 설명을 내부 메모로 대신한 문구

사용자는 구조도 Ethereum 영역의 ‘공개 검증 인프라’, ‘고객 BTC가 올라가는 체인이 아님’을 지적했다. Ethereum은 이 기획에서 KODA 발급 문서의 검증정보를 기록하는 곳이다. 그런데 화면은 그 역할보다 추상적인 분류와 설계 중 혼동을 막기 위한 부정문을 앞세웠다.

문제는 해당 문장이 사실인지에만 있지 않다. 청중이 그 위치에서 먼저 알아야 하는 내용을 자연스럽게 설명하는가가 중요하다. 같은 사실도 문서의 자산 항목, 구조도의 체인 역할, 기술 상세, 발표자의 보충 설명 중 어디에 두느냐에 따라 이해가 달라진다는 판단이다.

### 2. 기술 구현과 발표의 설명 순서가 같지 않다는 점

개발 과정에서는 PDF 생성, 해시, 서명, 등록 함수, RPC 등의 순서로 작업을 확인한다. 청중은 먼저 누가 어떤 증빙을 누구에게 제출하고 무엇을 확인하려는지 알아야 한다. 사용자는 발표자 관점에서 각 화면의 내용·정보·전달 방법을 다시 고민하라고 요청했다.

따라서 후속 검토는 ‘각 기능을 화면에 배치했다’에서 멈추지 않고, **업무 상황→검증할 질문→기술이 처리하는 입력과 결과→제3자의 확인**이 연결되는지 점검한다.

### 3. 표현의 어색함이 전체 완성도에 미치는 영향

사용자는 잘 쓰인 부분도 있음을 인정하면서, AI가 만든 듯한 추상 표현과 영어 번역투가 반복해서 눈에 걸린다고 말했다. 전체 문구를 일괄적으로 바꾸려는 것이 아니라, 청중의 목적과 맞지 않는 말·주체나 대상이 생략된 말·설계 대화를 그대로 옮긴 말을 구체적으로 찾아 고치려는 의도다.

### 4. 독립적 검증을 실제 근거로 설명하려는 요구

사용자는 제3자 UI에서도 블록체인 조회와 로컬 검증이 기술 처리로 이어진다는 점을 강조했다. ‘앞은 기술, 뒤는 UI’라는 구분으로는 전체 흐름을 전달할 수 없다. 제3자가 무엇을 입력하고 어느 기록을 읽으며 무엇과 비교하는지까지 보여주는 것이 목표다.

## 이번에 내린 작업 방식의 결정

현재 데모를 즉시 수정하지 않고, 다음 세 가지 원고를 먼저 준비한다.

- 장면별 전달 목적·필수 정보·동작·문구 후보·발표자 설명을 분리한 검토안.
- 사용 기술의 개념·작동 원리와 프로젝트 적용 이유를 함께 담은 PPT 부록. Q&A만으로 기술 설명을 대신하지 않는다.
- 사용자의 의도·문제 발견·판단과 구현 완료/검토 중 항목을 나누는 본 기록.

앞선 기술 검토에서 나온 발급서명 확인의 가시성, 사전 로드된 검증정보, 세 확인 항목의 의미, 등록 규칙과 체인 기반의 구분, 번호·글씨·사례 이름 문제도 함께 검토한다. 새 기술이나 업무 범위를 임의로 추가하지 않는다.

## 기여와 협업의 구분

**사용자 신기호의 기여**

- 팀에서 솔루션 부분을 맡고, 대표님 답변을 기준으로 과제의 목표와 제외 범위를 지속해서 점검했다.
- 자산 BTC와 검증정보 기록 체인 Ethereum을 구분하고, 실제 테스트 환경 Sepolia와 기획 체인의 표현을 분리하도록 판단했다.
- 증빙 원본 발급을 기존 업무로 보고, 추가하는 솔루션의 중심을 검증정보 기록과 제3자 대조·검증으로 좁혔다.
- KODA·고객사·제3자 역할과 전체 처리 위치를 보여주는 연출을 제안하고, 제품 UI는 제3자에게만 나타나도록 요구했다.
- 실제 컨트랙트·거래·조회까지 실증하기로 결정하고 지갑의 서명·거래를 직접 승인했다.
- 디자인 중심/과밀한 기술 설명 양쪽의 문제를 발견하고, 구조도와 현재 동작을 함께 보여주는 방향을 제시했다.
- 발표자의 관점, 화면 문구의 자연스러움, 기술 설명의 정확성을 다음 개선의 기준으로 정했다.

**AI 도구의 보조 범위**

공식 자료 검색·정리, 구현 코드와 문구 초안 작성, 테스트·화면 확인, 대안 검토, 의사결정 기록을 보조했다. 사용자 피드백을 기술·콘텐츠 검토 항목으로 구체화했다. AI가 작성한 코드나 리서치를 사용자가 모두 직접 작성했다고 표현하지 않는다.

## 향후 포트폴리오 소개문 초안

> KODA 산학협력 프로젝트에서 솔루션 설계와 기술 데모의 방향을 구체화했다. 대표님이 제시한 외부 증빙 검증 과제를 기준으로, 문서 검증정보의 블록체인 등록과 제3자의 대조 흐름을 설계하고 AI 도구와 함께 실제 테스트넷 실증을 진행했다. 이후 기술이 동작하는 것과 청중에게 잘 전달되는 것은 별개의 과제임을 발견했다. 업무 주체와 처리 위치를 연결한 구조도를 제안하고, 기술을 가리는 디자인과 정보가 과밀한 화면을 모두 검토했다. 현재는 대표님 답변·실제 구현·토스의 전달 원칙·보유 디자인 자료를 바탕으로 장면과 문구를 재설계하고 있다.

이 소개문은 현재 진행 상태를 설명한다. 최종 발표 성과나 고객 도입·업무 시간 절감 등 아직 확인되지 않은 효과를 덧붙이지 않는다.

## 후속 진행 — 추가 리서치 후 화면 반영

사용자는 기존 토스 리서치가 충분한지 다시 점검하고, 부족하면 추가로 조사한 뒤 수정하도록 요청했다. 새로운 공식 자료 두 편을 읽고 기존 자료 세 편을 재확인했으며, 신규 발견과 재검토를 구분했다. 여기서 얻은 기준은 제작자에게 익숙한 표현을 청중에게 설명하는 말로 바꾸고, 반복되는 장식 대신 실제 처리 결과를 보여주는 것이었다.

8개 장면의 표현과 구조도 역할 설명을 수정했다. 제3자 화면에서는 사전 제공된 검증정보, 발급서명 확인, Ethereum 조회, 세 해시 대조를 드러냈다. 색상과 기존 기술 검증 범위는 유지했다. 검토 중 로컬 계산 실패를 체인 조회 실패로 부를 수 있는 문제도 발견해 실제 실패 위치에 맞게 수정했다.

실제 Sepolia 조회에서 원본 일치와 변경본 불일치를 확인했고, 전체 live 테스트 30개와 빌드·브라우저 검사도 통과했다. 이번 검증에는 새 지갑 서명이나 거래 제출이 필요하지 않았다. 화면의 이해도 개선 효과는 아직 청중에게 검증받지 않았다.

사용자의 기여는 ‘더 조사하라’는 요구에 그치지 않는다. **대표님 답변·기술적 정확성·발표 전달력을 동시에 충족하는지 판단하고, 근거 있는 개선을 요구한 것**이다. AI는 자료 조회, 코드 수정, 회귀 검사와 기록을 수행했다. [리서치와 반영 근거](../../design/toss-research-application-2026-11-06.md)에 구현 및 검증 범위를 남겼다.
