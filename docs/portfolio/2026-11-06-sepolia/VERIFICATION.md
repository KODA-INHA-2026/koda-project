# 실제 등록·제3자 대조 결과

2026-11-06 04:11:08 KST(2026-11-05 19:11:08 UTC) 공개 Sepolia RPC 조회에서 등록 거래의 최종 확정과 두 PDF의 대조 결과를 확인했다. 정확한 확정 순간이 아니라 조회에서 관측한 시각이다.

등록 거래: [0x6c0d…c2d1e8](https://sepolia.etherscan.io/tx/0x6c0d68e1f292a3ba9322e733291c0b2fb8da4fbbfe505d0466613438b0c2d1e8).

| 대상 | 실제 결과 | 해석 |
| --- | --- | --- |
| 배포 코드·발급자·생성 인자 | 일치 | 사전에 고정한 시험 계약을 조회함 |
| 등록 거래·영수증·이벤트·정식 블록 | 일치 | 성공한 등록 입력이 이 발급 건과 연결됨 |
| EIP-712 서명 복원 | 시험 발급자 일치 | ID·해시·발급 기재시각에 대한 서명 |
| finalized 상태의 records | 등록 정보 일치 | 포함 상태만으로 성공을 선언하지 않음 |
| 100 BTC 원본 PDF | `match` | 전체 바이트 SHA-256 = 서명된 해시 = 체인 해시 |
| 120 BTC 변경본 PDF | `file-mismatch` | 제출 파일 해시만 다름. 원본 발급서명과 등록 정보는 그대로 유효 |

판정은 브라우저에서 사용하는 동일한 `verifyDocument` 함수에 실제 PDF 바이트와 공개 RPC를 전달하여 얻었다. 임의의 성공 응답이나 로컬 모의 체인을 사용하지 않았다. 원본 재현은 `pdf/reproduction.json`에 기록한 방식이며, 재현된 전체 바이트의 SHA-256이 이미 등록된 값과 일치함을 확인했다.

## 왜 이 결과가 중요한가

KODA의 내부 DB에서 “정상”이라는 답변을 받아 표시하는 대신, 제3자가 제출 파일에서 지문을 다시 계산하고 발급서명과 공개 계약 기록을 읽어 같은 기준으로 대조할 수 있음을 실증했다. 서비스 UI는 KODA 대시보드에 둘 수 있지만, 판정 근거를 그 대시보드의 내부 DB에만 두지 않는다.

이 구현은 공개 RPC 하나를 사용한다. RPC 제공자를 신뢰하지 않아도 되는 완전한 독립 검증이나 자체 노드 운영까지 구현한 것은 아니다. 외부 규격·코드 배포 경로와 운영상 신뢰 정책은 별도 작업이다.

## 증명하지 않는 것

- 문서에 기재된 실제 BTC 보유량, BTC 매수·수탁 사실, 현재 잔고.
- 시험 키 소유자가 실제 KODA의 공식 발급자라는 현실의 신원 연결.
- 발급자가 기재한 시각 자체의 진실성, 중간 변경 이력 전체, 문서의 현재 유효성.
- 변경본이 악의적 위조라는 판단. 여기서는 원본과 다른 바이트라는 사실을 판정한다.

## 재검증

```powershell
node --import tsx scripts/live/capture-registration.ts 0x6c0d68e1f292a3ba9322e733291c0b2fb8da4fbbfe505d0466613438b0c2d1e8 docs/portfolio/2026-11-06-sepolia/pdf/registered-original.pdf docs/portfolio/2026-11-06-sepolia/pdf/altered-120-btc.pdf
```

위 명령은 읽기 전용이다. 지갑 서명이나 새 거래를 요청하지 않는다. `registration-*.json`은 시점별 관측, `registration-latest.json`은 최근 관측이다. 앞선 대기 상태도 삭제하지 않고 남긴다.

새 회사명 **인하테크홀딩스㈜**는 다음 발급에 적용한다. 기존 한울테크홀딩스㈜ PDF를 바꾸지 않는다. 새 원본의 등록에는 사용자의 EIP-712 서명과 등록 거래 승인 두 단계가 필요하며 재배포는 필요 없다.
