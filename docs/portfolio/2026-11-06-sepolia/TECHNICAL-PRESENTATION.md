# 내용 중심의 전체 기술 시연으로 재설계

## 사용자가 바로잡은 핵심

디자인은 우리 솔루션을 표현하는 방식이다. Toss 자료를 적용한다는 이유로 기술명을 지우거나 실제 입력·출력을 숨기지 않는다. KODA·고객사·제3자는 업무 주체이고, Ethereum은 발급 등록과 제3자 조회에 함께 쓰는 인프라다. 앞은 기술·뒤는 UI라는 구분도 부정확하다. 제3자의 UI 조작 역시 로컬 암호 연산과 RPC 조회로 이어지는 전체 과정 안에 있다.

사용자는 첫 화면만 완성하고 멈추는 대신 전체 데모를 완성하도록 요청했다. 이에 기록 재생과 실제 실행이 공유하는 8개 장면 전체를 재작성했다.

## 구현한 변화

- 시작 화면을 KODA의 발급·등록, 고객사의 보관·제출, 제3자의 대조라는 병렬 업무 경계로 구성했다. 공통 Ethereum 기록은 등록 방향과 조회 방향으로 양쪽에 연결한다.
- PDF 전체 바이트, SHA-256 결과, EIP-712 domain과 typed data, ECDSA 서명, `register` 입력, 컨트랙트 검사, storage와 event, 영수증·finality를 기본 화면에 표시한다.
- 제3자의 서비스 창 옆에서 실제 검증 함수를 관찰한다. 완료·진행·실패는 함수 실행과 응답에서 발생하며 재생 타이머나 전역 busy 상태로 만들어내지 않는다.
- `authorizedIssuer`와 `records`는 처음 조회한 동일한 finalized 블록 번호에서 읽는다. 조회 중 finalized 높이가 전진해도 두 기준을 섞지 않는다.
- 단계별 관측값을 ID별로 갱신해 중복 행을 없앴다. 조회값이 없으면 등호·부등호 대신 미확인 표시를 유지한다. 미등록·미확정·조회 실패를 일치/불일치와 구분한다.
- 전체 장면을 흐리게 하는 fade를 제거하고, 데이터 경로의 이동에만 제한된 모션을 사용한다. KODA 초록·민트, 실제 코드·값의 가독성, 좁은 화면의 재배치를 유지한다.

새 기획 방향을 임의로 추가한 것이 아니라, 사용자와 대표님·COO가 정한 발급→서명·해시→등록→제3자 대조 흐름을 구현과 화면에 일치시킨 작업이다. 실제 운영 KODA 연동과 외부 JSON 배포는 완료했다고 주장하지 않는다.

## 검증

- 전체 live 테스트 21/21 통과: 결정적 PDF, 실제 로컬 EVM 계약, 권한·서명·중복·잘못된 입력, 영수증·정식 블록·finality, 원본·변경본 판정.
- 최종 검증기 테스트 8/8 재확인. 관측 콜백이 오류를 내도 검증 결과가 바뀌지 않는 조건을 포함한다.
- 웹·루트 TypeScript, live 프로덕션 빌드와 diff 검사 통과. 단일 번들 크기 경고는 별도 성능 개선 사항이다.
- 브라우저 검수와 실제 RPC 결과는 함께 보존하는 `technical-browser-qa.json` 및 `screenshots-technical/`을 확인한다. 테스트로 확인한 실패·대기 조건을 실제 Sepolia에서 새로 발생시켰다고 주장하지 않는다.
- 실제 Chrome에서 8개 장면 이동, 기록 재생·일시정지, Enter 키로 다음 장면 이동, 390px에서 모든 장면의 수평 넘침과 공통 Ethereum 표시를 확인했다. 원본은 `match`, 120 BTC 변경본은 `file-mismatch`; 두 관측에서 finalized 블록 12071669를 조회했다.
- 자동 파일 선택 검수는 확장 기능의 로컬 파일 접근 권한으로 막혔다. 해당 권한을 바꾸지 않았다. 잘못된 입력·조회 실패·미확정은 단위 테스트로 확인했으며, 해당 상태를 모두 실제 브라우저에서 주입·재현했다고 주장하지 않는다. 모션 축소 CSS는 코드로 확인했고 OS 설정 전환·스크린리더 세션은 실행하지 않았다.
- 브라우저 콘솔에 남은 경고는 MetaMask 확장의 `contentscript.js`에서 발생한 리스너·스트림 경고다. 확인한 마지막 오류/경고 목록에는 앱 코드 오류가 없었다.

## 개인 기여와 후속 승인

사용자는 솔루션 관점, 업무 주체와 인프라의 분리, 제3자 독립 검증의 기술적 의미, 실제 처리와 UI의 연결, 내용 우선 디자인 원칙을 결정하고 피드백했다. 코드 작성·공식 자료 조사·검증에는 AI 도구를 활용했다. 팀 기획과 기업 자문은 별도의 기여로 인정한다.

한울테크홀딩스㈜의 기존 등록 PDF는 보존했다. 인하테크홀딩스㈜의 새 등록은 [다음 승인 목록](USER-ACTIONS.md)에 모았다. 사용자가 쉬는 동안 새 지갑 승인이나 거래를 요청하지 않았다.
