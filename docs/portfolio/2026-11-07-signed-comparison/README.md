# 재서명 비교 사례 · 실제 승인과 구현 기록

## 사용자의 판단과 기여

신기호는 팀장 발표 흐름을 살리면서도, 기존 서비스 목적과 두 장면의 구성이 개별 피드백 때문에 흔들리지 않아야 한다고 요구했다. 이에 02의 같은 제3자 검증 화면에 비교 자료 선택만 추가했다. 새 문서 서명은 신기호가 MetaMask에서 직접 승인했다.

## 실제로 실행한 것

- 기존 100 BTC 등록 원본과 같은 문서 ID·발급 기재시각으로 120 BTC 비교 PDF의 해시를 다시 서명했다. 기재시각을 유지하는 비교 가정이며 새 서명이 그 시각에 만들어졌음을 뜻하지 않는다.
- 새 등록 거래는 보내지 않았다. 실제 EIP-712 서명·PDF 해시를 로컬에서 확인했다.
- 기존 등록의 거래 입력·영수증·이벤트·정식 블록·finality·발급자·저장값을 읽기 전용으로 검증했다.
- 실제 결과: 새 서명 유효 / PDF와 새 서명 일치 / Ethereum 등록 원본과 불일치.

`signed-comparison.json`은 사용자 승인 후 내려받은 자료를 검증해 보존한 공개 시험 서명이다. 개인키를 포함하지 않는다. `verification.json`은 실제 관측 시점과 검증 결과·trace이며, 웹의 검증 버튼은 새로 조회한다.

## 발표 흐름

01 발급·등록·고객사 전달 → 02 정상 원본 확인 → 필요하면 PDF만 변경한 경우 → ‘다시 서명한 문서’ 선택 후 같은 검증 버튼. 두 로컬 검사 통과와 공개 등록 원본 불일치가 동일 화면에 남는다. 지갑 승인은 준비 때만 필요하다.

이 사례가 보여주는 것은 유효한 서명과 이미 등록된 발급 기준의 차이다. 일반 전자서명으로도 파일 변경 탐지가 가능하며, 블록체인의 추가 가치는 발급기관 내부 DB와 분리된 공통 조회 기준이다. 실제 잔고·공식 법인 신원·현재 유효성까지 증명한다는 주장은 하지 않는다.
