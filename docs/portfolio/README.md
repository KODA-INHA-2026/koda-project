# KODA 프로젝트 개인 기여와 구현 기록

## 이 기록의 목적

사용자는 팀에서 솔루션 파트를 맡아 솔루션 설계, 기술 선택, 아키텍처, 데모 설계와 구현을 진행하고 있다. 이 과정을 나중에 포트폴리오로 설명할 수 있도록 결정의 이유와 실제 결과를 함께 보존한다.

모든 대화를 매번 옮기지 않는다. **중요한 방향 결정, 아키텍처 변경, 구현 완료, 실제 실행, 검증, 문제 발견과 수정 시점**에 기록한다. 각 기록에는 다음을 남긴다.

- 어떤 문제와 제약을 다뤘는가.
- 사용자가 직접 제안·결정하거나 구체화한 것은 무엇인가.
- 팀의 공통 방향과 대표님·COO 자문을 어떻게 반영했는가.
- 어떤 기술을 어디에, 왜 사용했는가.
- 실제로 무엇을 만들고 실행했는가. 코드·거래·테스트·화면 등 증거는 무엇인가.
- 검증 결과, 실패·대기·한계와 후속 작업은 무엇인가.

팀 전체의 성과를 개인의 단독 성과로 바꾸지 않는다. 대표님·COO의 방향, 팀 기획 초안, 사용자 주도의 솔루션 구체화, AI 도구가 보조한 코드 작성·검증을 구분한다. 기여를 축소하거나 과장하지 않고 실제 의사결정과 산출물로 설명한다. 현재 계획을 완료 성과로 쓰지 않는다.

## 보존 위치

1. 저장소의 `docs/portfolio/`: GitHub에 나중에 남길 수 있는 기록 원본.
2. 작업 폴더의 `기업 프로젝트/데모 개발/11.5일 대표님 답변 기준으로 최종결과물/포트폴리오 기록/`: 사용자가 정리하는 프로젝트 자료와 함께 보존.
3. 같은 이름의 Google Drive 프로젝트 폴더: 문서·공개 실행 증거·소스 스냅샷의 사본.

지갑 개인키·복구 문구·브라우저 세션·실제 고객 자료는 기록하지 않는다. 사용자가 승인한 시험 계정의 공개 주소와 Sepolia 거래는 구현 증거로 보존한다. 2026-11-06 사용자가 1차 피드백을 위한 GitHub 푸시와 공유 페이지 배포를 요청했다. 게시 정보는 [공유 기록](2026-11-06-sepolia/PUBLICATION.md)에 남긴다.
